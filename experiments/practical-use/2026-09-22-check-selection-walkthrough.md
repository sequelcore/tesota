# Source-and-test check-selection walkthrough: frozen protocol

This is one ordinary-shell diagnostic of the check-selection change, fixed before
the attempt. The task was used in the earlier pilot, so this is not a fresh
external-task qualification or an estimate of coding reliability. Retain a
failed, refused, timed-out or incomplete result without replacing the attempt.

## Input and task

- Product: the current local Tesota source and compiled CLI, including the
  application-selected proposal checks under evaluation. Record the source
  revision and working-tree state with the outcome.
- External repository: `Gentleman-Programming/gentle-pi` at committed baseline
  `5df9590e55b68717ea0cf8760eb9771c1dc9ed2b`, using a clean original clone.
  Tesota may write only through its own independent candidate.
- User request: "Fix requirement-body cleanup so an internal Markdown `---`
  divider is preserved and only a trailing section delimiter is removed. Add a
  regression test."
- One ordinary Tesota Shell attempt. Do not substitute the explicit proposal
  command, a developer API, a different model route or a replayed model output.
  Do not retry a failed attempt under this protocol.

## Predeclared observations

1. Discovery reads the relevant source and regression test from the committed
   baseline, then produces an admitted proposal with exactly `scope-integrity`
   and `node-test-targeted/v1`. A refusal or invalid result is retained.
2. If the proposal is ready, approve only its stated source and test paths and
   fixed check. Record any unexpected file, effect or check as a refusal.
3. A meaningful regression test must fail on the baseline behavior and pass
   on the corrected candidate. The internal divider must remain and the
   trailing delimiter must be removed. Inspect the exact test and source diff;
   a passing targeted Node check alone does not establish this behavior.
4. Record whether the ordinary conversation reaches exact-result review, the
   check claims and unknowns shown, the human decision, and whether accepted
   bytes are applied. Do not infer acceptance from a check result.

Record elapsed time, active operator work, setup burden, observed model/tool
work, unavailable usage or monetary cost, cancellation or settlement state,
and any residual defect observed. Docker and the pinned image must already be
available; Tesota must not pull an image or install dependencies during the
task. Stop if the required environment is unavailable.
