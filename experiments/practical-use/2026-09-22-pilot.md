# Practical-use pilot: frozen protocol

This is an internal diagnostic of the Tesota and Codex CLI product systems on
two preselected external repository tasks. It is not a model benchmark or a
claim of general coding superiority. The task set and scoring below were fixed
before either task attempt. Adverse, refused, failed and incomplete attempts
remain in the record.

## Systems and boundaries

- Tesota: local `63e710fbce55e7782ba0c9cad926aa57ff2870b7` plus the Pi
  `0.87.1` / `gpt-6-luna` route update under review. The route, package and lock
  identities are retained in the live smoke evidence; the ordinary compiled
  shell is the evaluation surface. No benchmark-only tool or permission is
  supplied.
- Comparator: Codex CLI `0.155.1`, invoked through its ordinary `exec` surface
  with `gpt-6-luna`, no model fallback, read-only sandbox for the question and
  workspace-write sandbox for the change. Its broader tools are a product
  difference, not controlled away.
- Same committed input bytes per paired task. Codex works only in an independent
  checkout. No candidate from this pilot is promoted into an original clone.
- One attempt per task per system: at most four task attempts plus the already
  separate Tesota route smoke. No retry for a bad result. A launch failure is
  retained as invalid, not silently replaced. Stop an active attempt at five
  minutes and retain any uncertain settlement. Setup and human waiting are
  recorded separately. Token and monetary cost are unavailable unless an
  authoritative per-attempt observation exists.

## Preselected tasks and independent checks

1. **Repository analysis, tgrep.** Baseline
   `microsoft/tgrep@56f8c62a2255d794bcaafca5f6a05dcc2d793ad0`.
   Request: "When can an indexed tgrep search miss a recently changed file,
   and how can I force a search of the current on-disk bytes? Distinguish the
   running-server and on-disk-index cases, and cite repository evidence."
   A satisfactory answer distinguishes asynchronous watcher processing from
   an index last published by `tgrep index`, identifies `--no-index` as the
   current-disk scan, and does not claim `tgrep status` proves freshness.
   No source mutation is requested.
2. **Source and regression test, Gentle Pi.** Baseline
   `Gentleman-Programming/gentle-pi@5df9590e55b68717ea0cf8760eb9771c1dc9ed2b`;
   task from [issue #1355](https://github.com/Gentleman-Programming/gentle-shell/issues/1355),
   whose proposed fix was still an open PR when selected. Request: "Fix
   requirement-body cleanup so an internal Markdown `---` divider is preserved
   and only a trailing section delimiter is removed. Add a regression test."
   The independent check first exercises a body with both internal and
   trailing dividers against the baseline and proposed result, then runs the
   repository's focused `openspec-deltas` tests. Correct source-only code
   without a meaningful regression test is incomplete for this task.

The repositories retain their actual configuration. Tesota's current source
task admission may refuse the Gentle Pi task; that refusal counts as a coverage
result, not as a model error. The tgrep question is a read-only overlap case.

## Accounting and decision

Record for each paired attempt: admitted or refused and why; final result and
independent check; time to a reviewable result; setup, active operator work and
waiting; clarification or correction; changed paths; evidence shown; and
application state. Keep typecheck/check success distinct from functional
correctness and human acceptance. With only two tasks, report per-task evidence
and failure causes, not a significance test or aggregate win rate. Use the
observed largest practical obstacle to choose one bounded follow-up; fresh
tasks are required for later qualification.
