# Keep request checks and evidence identities through settlement

**Status:** Proposed; implementation requested, human acceptance pending.
**Date:** 2026-11-02. **Owner:** Tesota's operator.

## Context

Settlement currently discovers checks after the agent worked. Whole-base test
sensitivity cannot identify which source paths a multi-file change exercised.
Receipt v2 stores model judgments beside mechanical contract strength.

## Decision

Extend existing owners as specified in the
[system design](2026-11-02-evidence-v3-design.md). Capture and show checks at
admission, compare baselines at settlement, measure source sensitivity through
bounded isolated reversions, and replace the receipt with one version-3
contract separating code evidence, specification evidence and request review.

The operator approved the admission/settlement timing, a two-minute extra
source-exercise budget per repository, and a twenty-minute live Sol/Luna
comparison through existing sign-in. There are no external consumers; no
compatibility adapter, dual writer or historical reconstruction is introduced.

## Consequences

Evidence becomes more precise without making model opinions authoritative.
Unsupported or unfinished source measurements remain explicit gaps. Existing
trust, freshness and attribution boundaries still apply. Old session formats
receive an unsupported-format result from the new receipt readers; their
original JSON and v2 specification remain intact.

Independent architecture review and its reproduced findings are recorded in
the design. Implementation checks support review; operator acceptance is pending.
No deployment or publication is authorized by this record.

Unresolved operator questions: none for implementation. Acceptance remains
with the operator.
